# 自己生成 Mirror 测试码

## 使用

首次后台配置完成后，在 Finder 打开项目的 `tools` 文件夹，双击 `生成Mirror测试码.command`：

1. 输入允许生成几次（1–100）。
2. 输入首次兑换后有效几天（1–30）。
3. 复制输出的完整测试码，私下发送给测试者。

示例：填 `3` 和 `7`，该码总共允许三次 AI 处理，首次兑换后七天过期。工具会联网向 Mirror 后台登记短码；登记不调用 AI，也不消耗 AI API 费用。实际 AI 处理仍消耗开发者 API 费用；处理前拒绝的照片返还额度。教学不另扣次数。

每个新码独立计数。同码多人共用总额度，重复兑换、换设备或重装不会增加额度。次数和有效期不能在已发出的码上直接修改；如需补发，请生成新码。不要把码公开贴到 LinkedIn。

记录在项目下忽略提交的 `private-fixtures/beta-admin/issued-codes.csv`。用表格打开查看历史，避免重复发同一码。该记录包含可兑换的私人码，请勿上传 Git 或公开分享。

## 一次性后台配置

工具首次运行会创建 `private-fixtures/beta-admin/issuer-secret.txt`（只允许文件所有者读写）。将同一密钥配置为 Vercel Production 的 `MAKEUP_BETA_CODE_SECRET`，部署包含本功能的后端后，新码才可兑换。未配置时工具生成的码并不代表已启用服务。

密钥授予发行免费 AI 额度的能力，不是 OpenAI API key，但仍须保密；不要发给测试者、写入 App 或提交 Git。以后生成码需要联网登记，但无需修改服务器配置或重新部署。删除 Vercel 中该密钥并重新部署会禁用此类新码及其会话；更换密钥也会使原码失效。旧的 SHA-256 邀请白名单继续独立支持。

## 实现

生成器内部仍使用带 HMAC-SHA256 签名的邀请，验证后登记 12 个随机字母数字组成的短码（例如 `ABCD-EFGH-JKLM`，仅示意）。短码与原邀请共用同一份额度；重复登记或使用长码不会重置次数或延长时间。原长码继续可用。服务器验证签名后首次兑换时用 Redis `SET NX` 创建额度和到期记录；并发额度扣除由 Lua 原子执行。签名和会话校验失败时不授予权限。无需新增数据库或公开管理员 API。未开通免费额度的普通匿名用户不能用此功能发行码。

这是外部 Beta 测试工具，正式上架前应重新评估保留方式。Apple 官方 TestFlight 邀请与免费 AI 次数是两个独立步骤。
